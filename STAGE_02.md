Разделитель и ширина столбцов регулируются.

## Запуск и проверка

Из папки проекта в Windows PowerShell с Python 3.12+ x64

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -X utf8 -m catalog check
.\.venv\Scripts\python.exe -m catalog gui
```

Обычный запуск берёт `catalog.db` из папки проекта. Для проверки удаления используйте отдельную копию.

```powershell
$testDb = Join-Path $env:TEMP ("dvd-catalog-" + [guid]::NewGuid() + ".db")
Copy-Item -LiteralPath .\catalog.db -Destination $testDb
.\.venv\Scripts\python.exe -m catalog gui --db $testDb
.\.venv\Scripts\python.exe -X utf8 -m catalog check --db $testDb
```

На копии выберите диск правой кнопкой и нажмите «Удалить диск из каталога…». Сначала проверьте «Отмена», затем повторите действие и подтвердите удаление.

## Реализация

Список запрашивает номера в числовом порядке. При выборе диска SQLite отдаёт только его корневые элементы, при раскрытии — прямых потомков конкретной папки. Оба запроса используют существующий индекс по диску и родительскому пути. Дерево сортирует размеры численно и сохраняет отображаемые имена с исходным регистром и точками.

Поиск по Enter или кнопке «Найти» создаёт рабочий поток Qt с собственным соединением SQLite в режиме чтения. Запрос ищет подстроку `str.casefold()` в поле `name_folded`. Поток передаёт до 256 строк за сигнал, а `QTableView` отображает их через модель без ограничения общего числа совпадений. Результаты упорядочены по номеру диска, имени без учёта регистра, полному пути и типу записи. Пустой запрос очищает таблицу и показывает подсказку в заголовке.

Удаление запускается из контекстного меню строки. Подтверждение указывает номер, объясняет, что изменяются только записи SQLite, и выделяет «Отмена» по умолчанию. Запись открывается отдельным соединением в режиме `rw`, без создания базы. Одна транзакция удаляет выбранный номер и его элементы через `ON DELETE CASCADE` с включёнными внешними ключами. После удаления показанная выдача очищается, чтобы не оставлять устаревшие строки.

К геометрии обоих окон, ширине панелей и колонок применяется `QSettings`. В Windows параметры хранятся отдельно от каталога в пользовательском разделе реестра `HKEY_CURRENT_USER\Software\DVD Catalog\DVD Catalog`. При отсутствии базы, с ошибкой чтения или с неизвестной версией схемы приложение показывает причину отказа. Команды этапа 1 сохраняют прежние форматы вывода и работают без Qt.

## Проверки на полном каталоге

Список содержал 1 516 номеров, отсортированных численно от №1 до №1517 с единственным пропуском №36. Раскрытые деревья №1512–1517 сверены с SQLite, в них соответственно 25, 26, 2, 3, 2 и 13 элементов. Архивы `Slavneft 2026.part1.rar` и `Slavneft 2026.part2.rar` отобразились на №1514 и №1515. На №157 проверена глубина родительского пути 11. Крупнейшая ветка из 2 980 строк загрузилась примерно за 45 мс в одном замере.

| Запрос | Строки в таблице | Медиана, мс |
| --- | ---: | ---: |
| `НЬЮРЕКСАН` | 16 папок | 37 |
| `ьЮРЕК` | 16 папок | 37 |
| `Slavneft` | 16 файлов | 39 |
| `1920x1080` | 541 файл | 39 |
| `.rar` | 7 627 файлов | 88 |
| `.` | 149 415 строк | 753 |

Замеры на компьютере разработчика учитывают время от запуска поиска до добавления последней порции в модель Qt. Для каждой строки таблицы показана медиана трёх запусков на копии базы, в режиме `offscreen`. Все строки, включая последнюю после прокрутки вниз, сверены с запросом SQLite по пути, номеру, размеру и дате со временем. Значения для контрольных запросов совпали с этапом 1.

До и после чтения копия побайтно совпадала с исходной базой. На оригинале подтверждены 1 516 дисков, 16 322 папки, 149 960 файлов, `integrity_check = ok` и ноль нарушений внешних ключей. На отдельной копии отмена удаления №1515 оставила файл базы побайтно прежним. Подтверждение удалило только №1515, одну папку и два файла. В копии осталось 1 515 дисков, 16 321 папка и 149 958 файлов, целостность и внешние ключи проверены.

## Автоматизированная и оконная проверка

**19 из 19 тестов прошли**, включая все 12 тестов импорта. Новые тесты покрывают индексированные запросы веток, ленивое раскрытие и числовую сортировку, Unicode-поиск по Enter, выдачу из нескольких порций, пустой поиск, отмену и подтверждение удаления, откат при ошибке каскада, восстановление геометрии и ширины колонок, а также отказ при отсутствующей, повреждённой или несовместимой базе.

Нативное окно запущено на Windows с отдельной копией архива. Через дерево доступности проверено открытое окно поиска с запросом `Бигам`. Заголовок показал 234 совпадения, в таблице присутствовали все шесть колонок и данные результатов. Захват кадра рабочего стола завершился тайм-аутом. Проверки веток, прокрутки, удаления и геометрии выполнены автоматически через Qt на Windows.

## Файлы и ограничения

- `catalog/gui.py` — главное окно, дерево, контекстное меню и сохранение размеров.
- `catalog/search_window.py` — окно поиска, фоновый поток, табличная модель и форматирование полей.
- `catalog/database.py` — запросы номеров и веток, чтение расширения для GUI и транзакционное удаление.
- `catalog/__main__.py` — команда `gui` с параметром `--db`.
- `requirements.txt`, `tests/test_gui.py` и `stage_02/*.png` — зависимость Qt Widgets, тесты и снимки.
- `AGENTS.md`, `SPEC.md`, `README.md` — актуализированы границы этапа и инструкция запуска. В `.gitignore` исключены локальные окружения.

Проверки проведены на Windows 10 x64. Windows 11 отдельно не проверялась. Поиск хранит полученные строки в памяти до следующего запроса либо закрытия приложения. Сканирование носителей и выпуск автономной сборки относятся к следующим этапам.
