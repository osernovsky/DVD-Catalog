# Задача Codex №02: графический интерфейс и поиск

## Контекст и границы этапа

Этап 1 принят пользователем. Прочитай `README.md`, `SPEC.md`, `AGENTS.md`, `STAGE_01.md` и текущий код проекта. **Сохрани существующий импортёр, формат SQLite и команды этапа 1.** Используй уже созданную базу `catalog.db`, содержащую 1 516 дисков, 16 322 папки и 149 960 файлов.

**Реализуй только этап 2:** главное окно, просмотр содержимого дисков, поиск и удаление записи диска через контекстное меню. Не реализуй сканирование и добавление новых CD/DVD, установщик или финальную портативную сборку `.exe` — это следующие этапы.

В `AGENTS.md` пока записано, что разрешён только `TASK_01.md`, а в `SPEC.md` удаление было предварительно отнесено к этапу 3. Пользователь уже принял этап 1, а в текущем задании **явно переносит удаление в этап 2**. В начале работы аккуратно актуализируй эти два пункта в `AGENTS.md`, `SPEC.md` и, при необходимости, в `README.md`, не меняя остальных согласованных требований. По завершении этапа 2 остановись и дождись приёмки.

## 1. Технология и запуск

- Windows 10/11 x64, Python 3.12+, **PySide6 (Qt Widgets)**. Используй существующий пакет `catalog/` и существующие классы/запросы из этапа 1, не переписывай успешно проверенный импорт.
- Пока достаточно запуска из исходного кода в среде разработчика, например `python -m catalog gui`; добавь понятную команду запуска в `README.md`. Конечный пользователь получит автономную сборку на этапе 4.
- Путь к базе должен определяться предсказуемо; по умолчанию использовать `catalog.db` в папке проекта на этапе разработки. Допускается параметр `--db` для тестирования на копии и будущего портативного запуска. Не хранить абсолютные пути к XML или исходному компьютеру в БД.
- **Не пересоздавать и не импортировать базу автоматически при открытии GUI.** При отсутствии базы, неподдерживаемой версии или ошибке чтения показывать понятное сообщение, не создавать пустую базу взамен рабочей.

## 2. Главное окно

- Спокойный, компактный интерфейс на русском языке, максимально похожий по логике на согласованные скриншоты WhereIsIt. Никаких лишних вкладок, панелей, боковых фильтров и настроек.
- Вверху ровно две основные кнопки: **«ДОБАВИТЬ ДИСК»** и **«ПОИСК»**. На этапе 2 «ДОБАВИТЬ ДИСК» **неактивна**, поскольку сканирование физических дисков ещё не реализовано.
- Основная область разделена вертикальным перемещаемым разделителем (`QSplitter` или эквивалент): **слева** прокручиваемый список физических носителей, **справа** содержимое выделенного носителя.
- Список слева отсортирован по **числовому** номеру диска по возрастанию: `1, 2, 3, …, 1517`, с отсутствующим №36. Показывать прежде всего нанесённый на физический диск номер, а не метку вроде `New (267)`. На дисках старого архива не создавать искусственные элементы.
- Справа — привычное дерево папок и файлов выбранного диска, с раскрытием и сворачиванием папок. Показывать **имя**, **расширение**, **размер**, **дату** (если есть). Изменение ширины столбцов, прокрутка, выбор строки и сортировка должны вести себя привычно для Windows. Имена файлов с расширениями отображать без потери точек и оригинального регистра.
- Поддерживать файлы в корне, вложенность как минимум до 11 уровней, пустые или отсутствующие даты, файлы без расширений, имена вида `.DS_Store`, размеры файлов свыше 4 ГиБ, имена на русском и латинице.
- При выборе диска не загружать все 166 282 записи в дерево; выбирать нужные записи из SQLite. Желательно ленивое наполнение веток дерева при раскрытии. Интерфейс должен оставаться отзывчивым при переключении дисков и раскрытии больших папок.

## 3. Поиск по всему архиву

- Отдельное компактное окно, вызываемое кнопкой **«ПОИСК»**. В нём **только** поле для строки поиска, кнопка **«Найти»** и таблица результатов. Клавиша **Enter** запускает поиск. Никаких чекбоксов, сложных режимов, регулярных выражений, категорий или поиска внутри содержимого файлов.
- Искать **по любой подстроке отображаемого имени файла или папки** одновременно по всему каталогу; без учёта регистра, с корректной Unicode-обработкой кириллицы. Использовать готовое поле `name_folded` и ту же семантику `str.casefold()`, которые описаны в `STAGE_01.md`.
- Поиск должен включать все совпадения, в том числе одноимённые элементы на разных дисках. **Не ограничивать результат первыми N записями без ведома пользователя.** При большом ответе применять постраничное/порционное получение для таблицы без потери результатов.
- Таблица результатов: **название**, **расширение/тип**, **размер**, **дата**, **путь внутри диска**, **номер диска**. Номер диска — отдельная отчётливая колонка. Поддержать изменение ширины колонок и прокрутку.
- Для пустого запроса не запускать бессмысленную выдачу всех элементов: оставить таблицу пустой и вывести короткое сообщение или подсказку.
- Не блокировать графический интерфейс на длительном поиске: использовать рабочий поток или иную корректную модель фоновых запросов Qt с безопасной передачей результатов в UI. Учесть, что соединения SQLite нельзя бездумно использовать из другого потока; открывать отдельные соединения при необходимости.
- Сортировка результатов должна быть стабильной и понятной (например, по номеру диска и полному пути). Не изменять записи ради поиска.

## 4. Удаление диска через контекстное меню

- **Никакой кнопки удаления в интерфейсе.** В левом списке по правому клику на конкретном диске — действие **«Удалить диск из каталога…»**.
- Прежде чем удалить, обязательно показать подтверждение с точным **номером диска**, пояснением, что удаляются **только записи в базе**, а файлы на физическом CD/DVD не затрагиваются. По умолчанию безопасный вариант — «Отмена».
- При подтверждении удалить выбранный диск и его элементы **одной транзакцией** с использованием существующей схемы `ON DELETE CASCADE` и `PRAGMA foreign_keys=ON`. При ошибке — откат, сообщение, отсутствие частичного удаления.
- Удаление проверить **только на копии** `catalog.db`, не на оригинальной рабочей базе пользователя. Добавить тест удаления и отмены. Не требовать проверки функции на настоящем архиве пользователя до его отдельного решения.

## 5. Настройки окон

- Автоматически запоминать размеры и положение окон, ширину панелей и колонок, чтобы при следующем запуске не настраивать интерфейс заново.
- Эти необязательные настройки должны храниться **отдельно от `catalog.db`**, чтобы БД оставалась самостоятельным переносимым архивом. Подойдёт `QSettings` или небольшой конфигурационный файл. Отсутствие настроек не препятствует запуску; корректное расположение окон по умолчанию обязательно.
- Не создавать отдельный экран настроек.

## 6. Безопасность данных и ограничения

- Открытие диска и поиск **только читают** SQLite. Для отладки GUI использовать копию исходной `catalog.db`; разработка интерфейса не должна изменять 20-летний архив.
- Не трогать `input/whereisit.xml`, оригинальные `.CTF`/`.BAK` и импортные файлы. Не делать скрытого импорта, миграции схемы, очистки записей или автоматической резервной копии.
- Поддержать существующую **версию схемы 1**, не менять её без доказанной необходимости и без сохранения обратной совместимости с командами этапа 1. Принцип — минимум изменений в проверенном ядре.
- Ничего из внеобъёмного списка `SPEC.md` не добавлять: теги, категории, предпросмотр, метаданные видео, облако, веб-интерфейс, автоматическое резервирование, контроль здоровья DVD и т. п.

## 7. Проверки и критерии приёмки

1. До и после **чисто читающих** GUI-сценариев `catalog.db` сохраняет 1 516 дисков, 16 322 папки, 149 960 файлов; `PRAGMA integrity_check = ok` и внешние ключи корректны.
2. В левой панели видны реальные номера; **№36 нет**, последний **№1517** есть. Список не сортируется лексикографически (`1, 10, 100, …`).
3. Дерево корректно показывает выбранные диски №1512, 1513, 1514, 1515, 1516 и 1517; на №1514 виден `Slavneft 2026.part1.rar`, на №1515 — `Slavneft 2026.part2.rar`.
4. Поиск по `НЬЮРЕКСАН`, `ьЮРЕК`, `Slavneft`, `1920x1080` и `.rar` корректен, учитывает файлы и папки, регистр и частичные совпадения. Для **точного** имени `НЬЮРЕКСАН` в исходной базе отчёт этапа 1 указывает **16 папок**, для `1920x1080` — **541 файл**, для `.rar` — **7 627 файлов**: эти значения использовать как контрольные, учитывая, что в таблице могут быть также совпадения другого типа.
5. В поисковой таблице все найденные строки содержат правильные номера дисков, пути, размеры и даты. Нет обрезания выдачи и исчезновения результатов при прокрутке.
6. Интерфейс отзывчив при работе с полной базой, поиска по частому расширению и переключении между дисками. Сообщить измеренное время типовых поисков на компьютере разработчика; без необоснованных обещаний фиксированной скорости.
7. Удаление выбранного диска на **копии** базы требует подтверждения; отмена оставляет базу неизменной, подтверждение удаляет только выбранный диск со всеми его записями. Остальные диски сохранны, проверка SQLite успешна.
8. После закрытия/открытия окна сохраняют удобный размер, положение и ширину колонок; отсутствие файла настроек не мешает запуску.
9. Все тесты этапа 1 остаются проходящими. Добавлены проверяемые автоматизированные тесты для новых запросов/моделей и удаления; для GUI-сценариев выполнена реальная ручная проверка на Windows.
10. Кнопка «ДОБАВИТЬ ДИСК» видна, но неактивна; **ни один** новый физический диск на этом этапе не сканируется и не добавляется.
