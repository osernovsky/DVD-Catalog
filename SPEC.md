# DVD Catalog — согласованное техническое задание

## 1. Назначение и ограничения

Локальный быстрый каталогизатор физических CD/DVD рабочих видеопроектов вместо WhereIsIt. Пользователь **сначала** записывает DVD в Nero, **после успешной записи** вставляет его в привод и добавляет в каталог. Режим предварительного учёта ещё не записанных папок **не нужен**.

Платформа: Windows 10/11 x64. Приложение полностью офлайн, без учётной записи, подписки, сервера или сетевых служб. Портативный запуск без установки и без наличия Python у пользователя. Разработка: Python 3.12+, GUI PySide6/Qt, база SQLite, сборка PyInstaller. Возможна подпапка `_internal` с упакованными библиотеками при использовании `onedir`; при возможности предпочтителен удобный для пользователя exe и отдельная БД.

## 2. Главное окно

- Два изменяемых по ширине раздела: **слева** вертикальный список физических дисков, по возрастанию номеров; **справа** содержимое выбранного диска в знакомом Проводнику дереве папок и файлов. Сворачивание/раскрытие папок, клики и прокрутка.
- В списке дисков главный идентификатор — нанесённый на физический носитель **номер**, а не произвольный системный том `New`/`Archive`.
- Справа показывать имена, расширения, размеры и даты (стандартные колонки). Вложенные папки и файлы в корне обязательны.
- Ровно две **основные** кнопки: `ДОБАВИТЬ ДИСК`, `ПОИСК`. Дополнительные постоянные панели, кнопки, вкладки и настройки не нужны.
- Удаление диска реализуется **на этапе 2**, только из контекстного меню левой панели по правой кнопке и с подтверждением. Удаление касается исключительно записей SQLite.
- Размер и положение окон, ширина панелей и колонок сохраняются отдельно от базы.

## 3. Поиск

- Отдельное компактное окно: одно поле ввода, одна кнопка `Найти`, Enter запускает поиск. Без флажков, регулярных выражений, категорий и сложных режимов.
- Искать **по названию файла и папки**, без учёта регистра, по любому фрагменту строки; корректно обрабатывать русские буквы. Не искать по описаниям и содержимому файлов.
- Показать **все совпадения**, даже если имена одинаковы на разных физических дисках. В таблице результатов: название (расширение для файла), размер, дата, путь внутри диска и **номер диска**. Разумная сортировка по номеру и имени; поддерживать прокрутку и изменение ширины колонок.
- Учитывать размер текущей базы (149 960 файлов + 16 322 папки); обеспечить отзывчивость UI. Python `str.casefold()` или эквивалент для Unicode; SQLite `NOCASE` без расширения не покрывает всю кириллицу.

## 4. Добавление нового физического CD/DVD

- Только после записи в Nero и при наличии носителя в оптическом приводе. Выбор доступного CD/DVD-привода при необходимости.
- Сканировать реальную файловую систему диска с полной вложенностью, не читая содержимое файлов, а собирая метаданные: имя, вид, размер в байтах, дата/время, относительный путь.
- Предлагать `max(существующих номеров) + 1`; для исходной базы это **1518**. Разрешить вручную изменить номер. Не допускать повторного номера.
- Избегать подвисания интерфейса при сканировании.
- Только после **полного успешного** чтения фиксировать новый диск одной транзакцией. На любой ошибке чтения, отключении привода или отмене **не оставлять** частично добавленного DVD в каталоге.

## 5. База данных и резервное копирование

- Все данные в **одном** переносимом `catalog.db`, располагаемом рядом с `DVD-Catalog.exe` в доступной для записи папке. Никакого обязательного внешнего конфигурационного файла.
- База остается на месте при обновлении exe. Для резервирования закрыть программу и скопировать `catalog.db` на отдельный DVD с надписью `КАТАЛОГ`. Для восстановления — вернуть файл обратно. Из коробки нет автоматического резервирования.
- Предпочесть `journal_mode=DELETE` (не требовать `-wal` и `-shm` после корректного завершения), `foreign_keys=ON`, транзакционные операции, проверку `PRAGMA integrity_check`.
- Предлагаемая схема: `discs` (`disc_num INTEGER PRIMARY KEY`, `volume_label`, `media_type`, версия схемы); `entries` (`id INTEGER PRIMARY KEY`, `disc_num`, `kind File/Folder`, `parent_path`, `name`, `extension`, `size_bytes INTEGER`, `modified_date`, `modified_time`). Хранить относительные пути и исходное написание имён/расширений, сохранить байты размеров. При необходимости добавить вычисляемые поля для быстрого поиска. Индексы по дискам/родительским путям; конкретную схему Codex должен оформить в документации.
- Нельзя включать `whereisit.xml` внутрь рабочей БД после импорта: необходимы только данные каталога.

## 6. Миграция из WhereIsIt

- Импорт из полного `whereisit.xml` — **однократная техническая операция**, не третья кнопка главного окна. Пользовательский исходник не изменять.
- Формат: XML UTF-8 `<REPORT>` с `<ITEM ItemType="File|Folder">`, поля `NAME`, опциональное `EXT`, `SIZE`, `DATE`, `TIME`, `DISK_NUM`, `DISK_NAME`, `DISK_TYPE`, `PATH`; опциональные `DESCRIPTION` и `CRC` не требуются для функционала.
- `EXT` в XML отделён от `NAME`. Для отображения/поиска файлов собирать `NAME + '.' + EXT` только когда EXT заполнено; исходный регистр не менять.
- `PATH` — путь **родительской папки** с обратной косой чертой; `\` означает корень. Сохранять древовидную структуру на каждом физическом диске, независимо от глубины. Бывают файлы без расширения и файлы непосредственно в корне.
- В XML встречаются запрещённые XML 1.0 управляющие байты. Сделать документированную **потоковую** ограниченную фильтрацию **только** этих символов (C0, кроме TAB/LF/CR) при чтении, не переписывая оригинал. Не использовать широкую замену нераспознанного текста и не менять кириллицу. Считать число удалённых байтов, показывать в отчёте. Любые другие ошибки разбора — явная ошибка, не молчаливое игнорирование.
- Не переписывать существующий `catalog.db` в случае повторного импорта. Строить временный новый SQLite-файл, полностью проверять число записей и связи, `integrity_check`, затем атомарно устанавливать как базу **только при отсутствии активной базы** (или по отдельной явной процедуре замены с подтверждением пользователя).
- Если импорт сломан/прерван, не должно оставаться ложной готовой базы. При повреждениях данных — отчёт с дисками и причинами.
- Сохранить **существующую** последовательность номеров от 1 до 1517, где №36 отсутствует. Не создавать запись с №36 и не сдвигать остальные номера.

## 7. Приемочные испытания

- После импорта: ровно **1516 дисков**, **16322 папки**, **149960 файлов**, суммарно **166282** записей. Пропущен только №36.
- Все ссылки на родительские папки действительны, нет дубликатов логических путей/элементов в пределах одного DVD.
- Диск 1514: `Slavneft 2026.part1.rar`; диск 1515: `Slavneft 2026.part2.rar`. Файлы правильно локализуются поиском.
- Примеры поиска: `Ньюрексан`, `Slavneft`, `1920x1080`, файловые расширения и неполные фрагменты имён. Совпадения по именам каталогов и файлов корректны.
- Учитывать старые **CD-R** и DVD разных типов, файлы без расширения, вложенность до 11 уровней, крупные файлы `>4 GiB`.
- В новой чистой базе следующий предлагаемый номер — 1518. При сканировании повторного номера или ошибке носителя база неизменна.
- Копирование закрытого `catalog.db` в другую папку и открытие его программой полностью восстанавливает структуру и поиск.
- Готовая сборка запускается на чистой Windows 10/11 x64 **без** Python, Qt или установки; тестировать фактически, не считать гарантирующим один только успешный PyInstaller build.

## 8. Вне объёма первой версии

macOS, веб-интерфейс, смартфоны, теги, категории, обложки, предпросмотр, метаданные видео, контрольные суммы DVD, проверка читаемости, экспорт CSV, учёт мест хранения, автоматически управляемые резервные копии, предварительное добавление проектов до записи DVD и любые другие не согласованные функции.
