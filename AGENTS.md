# Правила разработки DVD Catalog

1. Строго следуй `SPEC.md`. Не добавляй теги, категории, описание проектов, превью, cloud, web, сервер, вход в аккаунт, проверку состояния DVD, контрольные суммы, автоматические резервные копии или необязательные настройки сверх согласованного запоминания окон и ширины панелей и колонок.
2. Работай по этапам. **Сейчас разрешён только `TASK_03.md`**: добавление записанных CD/DVD и проверки в ветке `feature/dvd-scanning`. После отчёта остановись для приёмки. Портативная сборка требует отдельного согласования.
3. Не удаляй и не перезаписывай оригинальные файлы WhereIsIt (`.CTF`, `.BAK`, XML). Не изменяй источник XML, особенно ради исправления управляющих символов. Все преобразования делай только при чтении/в рабочей копии.
4. При импорте сохраняй реальные номера дисков и **все** записи; отсутствующий №36 допустим и не должен появиться искусственно. Все ошибки отражай в отчёте, не пропускай молча целые записи.
5. Используй переносимую архитектуру, но реализуй и тестируй только Windows 10/11 x64. Основной стек Python 3.12+, стандартный `sqlite3`, PySide6 для будущего GUI, PyInstaller для итогового выпуска. Для текущего этапа избегай ненужных зависимостей.
6. Все изменения схемы БД делай осознанно, с явным номером версии схемы; пользовательская БД не должна заменяться молча при обновлении приложения.
7. База `catalog.db` — отдельный пользовательский файл рядом с exe. Предпочесть SQLite `journal_mode=DELETE` с транзакциями: после штатного закрытия программы для переноса достаточно одного `catalog.db`.
8. В UI должны быть только две основные кнопки — «ДОБАВИТЬ ДИСК» и «ПОИСК». Удаление реализуется на этапе 2 правой кнопкой по диску с подтверждением.
9. Проверяй тестами кодировку UTF-8, Unicode casefold для кириллицы, вложенные папки, файлы в корне, файлы без расширения, размер более 4 GiB, одноимённые файлы на разных дисках, повреждённый ввод, прерванный импорт, повторные номера дисков.
10. После каждого этапа публикуй по-русски: что сделано, какие тесты выполнены и их результаты, фактические числа, известные ограничения, как запустить и проверить. Не заявляй о работоспособности без проверки.
11. Если оригинальный `whereisit.xml` недоступен в рабочей среде, сообщи об этом и запроси помещение локальной копии в `input/`; не подменяй реальный архив синтетическими данными, кроме отдельных тестовых фикстур.
12. Не начинай следующий этап без явного согласования. В сомнительных случаях выбирай простейшую реализацию, соответствующую заданному поведению.
