# Этап 3. Добавление записанных CD/DVD

Работа выполнена в локальной ветке `feature/dvd-scanning` от стабильного коммита `11d3958`. Ветка `main` осталась на этом коммите.

## Как работает добавление

1. Завершите запись в Nero, вставьте записанный диск и нажмите **«ДОБАВИТЬ ДИСК»**.
2. Приложение обнаружит оптические приводы Windows. При одном читаемом томе привод выбирается автоматически, при нескольких доступен список. Диалог показывает букву привода, метку тома и предлагаемый номер `MAX(disc_num)+1`. Номер можно изменить вручную.
3. Нажмите **«Сканировать»**. В фоне читаются имена и файловые метаданные, включая корневые файлы и пустые папки. Диалог показывает текущий путь и счётчики. Размер папки равен сумме байтов файлов во всей её ветке. Дата и время сохраняются в локальном представлении.
4. После успешного обхода один диск и все его элементы сохраняются одной транзакцией SQLite. Новый номер сразу выделяется в списке, дерево открывается, прежняя выдача поиска очищается. Сообщение об успехе содержит количества файлов и папок.

Например, для пустого привода появляется просьба вставить записанный диск, для занятого номера — сообщение «Диск №1517 уже есть в каталоге». Ошибка перечисления, чтения метаданных, изменение тома или ошибка SQLite прерывают добавление. Отмена действует до начала `COMMIT`. Если Windows ещё выполняет запрос к приводу, диалог остаётся отзывчивым и дожидается выхода из этого запроса.

Новые носители сохраняются с типом `Optical`. Windows сообщает класс привода и свойства тома, по которым нельзя надёжно выбрать маркировку вроде `DVD+R` или `CD-R`. Перед обходом, после него и перед коммитом сверяются доступность корня, метка, серийный номер тома и файловая система. Эти свойства могут совпасть у двух носителей. Сканирование читает метаданные и не проверяет содержимое файлов или качество записи Nero. Ссылки и точки повторной обработки прерывают добавление. [GetDriveTypeW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdrivetypew), [GetVolumeInformationW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getvolumeinformationw)

## Результаты проверки

**33 из 33 тестов прошли** на Windows 10 x64 с Python 3.12.14 и PySide6 6.12.0. Сохранено покрытие 24 сценариев стабильной версии, а ожидание неактивной кнопки обновлено для этапа 3. Добавлено 9 тестов.

- Проверены русские имена, расширение в исходном регистре, `part1.RAR`, `.DS_Store`, файлы без расширения, пустые и вложенные папки, размер свыше 4 ГиБ и суммы размеров папок.
- Проверены отсутствие привода, пустой привод, недоступный корень, ошибки перечисления и `stat`, отклонение точки повторной обработки, смена или извлечение носителя перед коммитом, откат при ошибке SQLite и отмена во время обхода и перед коммитом.
- Проверены выбор из нескольких томов, занятый номер, конкурентные попытки с одним номером, повтор после ошибки или отмены, обновление дерева и поиск нового элемента без перезапуска. Таймер Qt сработал во время фоновой операции и отменил её через диалог.

В нативном GUI на временной копии полного архива предложен **№1518**, а №36 остался пропуском. Добавление тестового источника создало **2 файла и 2 папки**. После операции на копии было **1 517 дисков, 16 324 папки и 149 962 файла**. Все прежние строки обеих таблиц совпали с исходной копией. `PRAGMA integrity_check` вернул `ok`, нарушения внешних ключей, потерянные родители и дубликаты отсутствуют. Версия схемы — 1, режим журнала — `delete`. Рабочая база побайтно совпала с исходной копией и содержит 1 516 дисков, 16 322 папки и 149 960 файлов.

**Физический носитель.** После установки записанного диска Windows обнаружила том UDF в приводе `E:\`. Через нативное окно добавления диск записан как №1518 в отдельную временную копию. Сохранены **8 файлов и 5 папок**, суммарный размер файлов — **3 041 732 728 байт**. Независимый обход привода подтвердил все 13 записей, включая метаданные, регистр, полный путь и суммы размеров папок. Дерево выбрало №1518, поиск с изменённым регистром нашёл файл на новом диске. Повторно предложен №1519, а попытка использовать занятый №1518 отклонена. Отмена до начала обхода и отказ при повторном номере оставили соответствующие копии побайтно прежними.

На тестовой копии после добавления **1 517 дисков, 16 327 папок и 149 968 файлов**. Старые строки обеих таблиц идентичны, `integrity_check = ok`, нарушений внешних ключей нет. Добавление заняло **0,22 с** в одном замере после независимого обхода того же диска. Рабочая база побайтно совпала с эталонной копией. Тесты на Windows 11 и физическое извлечение во время обхода не проводились. Содержимое файлов не читалось.

## Как проверить на своём диске

Из папки проекта в PowerShell с Python 3.12+ x64

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
$testDb = Join-Path $env:TEMP ("dvd-catalog-stage03-" + [guid]::NewGuid() + ".db")
Copy-Item -LiteralPath .\catalog.db -Destination $testDb
.\.venv\Scripts\python.exe -m catalog gui --db $testDb
.\.venv\Scripts\python.exe -X utf8 -m catalog check --db $testDb
```

Закройте экземпляры каталога перед копированием. В открывшемся окне добавьте готовый диск, сверьте номер, раскройте вложенные папки и найдите один из новых файлов через поиск. Для проверки отмены начните добавление другого диска и нажмите «Отмена» во время обхода, затем повторите `catalog check` на копии.

## Файлы

- `catalog/disc_scanner.py` — приводы Win32, чтение метаданных и управление отменой.
- `catalog/add_disc_dialog.py`, `catalog/gui.py` — диалог, фоновый поток, обновление дерева и поиска.
- `catalog/database.py`, `catalog/importer.py` — транзакционная вставка и общий SQL для записи элементов.
- `tests/test_disc_scanner.py`, `tests/test_gui.py` — автоматические проверки.
- `AGENTS.md`, `README.md`, `TASK_03.md`, `STAGE_03.md`, `.gitignore` — границы этапа, инструкция, отчёт и исключение локальных снимков.
