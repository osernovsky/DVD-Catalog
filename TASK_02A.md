# TASK_02A — Визуальная доработка поиска и иконки файлов

## Контекст

Проект: **DVD Catalog**, локальный портативный каталогизатор оптических дисков для Windows 10/11.

Этапы 1 и 2 уже реализованы. Рабочая база `catalog.db` импортирована из WhereIsIt; **1516 дисков, 16322 папки, 149960 файлов**. Существующие операции просмотра дисков и поиска работают. В окне поиска сейчас все результаты показаны одной плоской таблицей, из-за чего трудно визуально отличить папки, видеозаписи, архивы и прочие материалы.

**Задача этого документа — небольшая доработка этапа 2, без перехода к этапу 3.** Нужны визуальная группировка найденного и привычные иконки типов файлов, как в WhereIsIt.

## 1. Результаты поиска: группы по типам

Вместо единой плоской таблицы представь результаты в дереве/таблице с **восемью визуальными группами**:

1. **Папки**
2. **Видео**
3. **Аудио**
4. **Архивы**
5. **Изображения**
6. **Проекты / исходники**
7. **Документы**
8. **Прочее**

Требования к группировке:

- Группы представляют **только способ отображения**, а не фильтр и не новую сущность в SQLite.
- В каждой группе показывай количество совпадений: например, `Видео (14)`, `Архивы (2)`.
- Сначала показывай только непустые группы; все непустые группы **изначально раскрыты**, но пользователь может их свернуть и раскрыть.
- Внутри групп сохраняй таблицу и существующие колонки: **Название**, **Расширение / тип**, **Размер, байт**, **Дата**, **Путь внутри диска**, **Диск**.
- Данные каждого результата (имя, регистр, размер, дата, путь, номер диска) должны остаться **строго такими же**, как до доработки. Один найденный элемент должен встречаться в выдаче **ровно один раз**.
- В строке заголовка группы не имитируй файл: сделай её отчётливо отличимой (например, полужирный текст и ненавязчивый фон). Не добавляй отдельную «шапку» с этими же группами.
- Сохраняй предсказуемый порядок групп, указанный выше; внутри каждой группы — стабильный порядок результатов (предпочтительно как раньше: диск, имя, путь).
- Итоговый счётчик результатов должен показывать количество **файлов и папок, а не заголовков групп**.

## 2. Иконки

- Добавь небольшую, отчётливую иконку **перед именем** каждого файла и папки в **результатах поиска**.
- Добавь те же иконки в **правое дерево содержимого диска** в главном окне.
- Используй единый стиль и размеры иконок (примерно 16×16 px при стандартном масштабе интерфейса, с корректным отображением при DPI-масштабировании Windows).
- Достаточно восьми базовых узнаваемых пиктограмм: папка, видео, аудио, архив, изображение, проект, документ, прочий файл.
- Допустимо использовать системные иконки Windows по типу расширения с локальным кэшированием и гарантированным запасным набором иконок в составе приложения. **Нельзя требовать, чтобы физический DVD был вставлен**: иконки строятся по метаданным каталога, а не по существованию исходного файла.
- Отрисовка иконок не должна требовать интернета или заметно замедлять прокрутку и поиск. Не выполнять дорогостоящий запрос к Windows Shell для каждой строки.
- Не добавляй миниатюры и предварительный просмотр содержимого файлов.

## 3. Классификация расширений

Сделай одну небольшую централизованную функцию определения типа файла, используемую в обоих окнах. **Сравнение расширений без учёта регистра** (`.AVI` и `.avi` равнозначны). Базовые правила:

| Группа | Примеры расширений |
| --- | --- |
| Папки | Определяются по `kind=Folder`, независимо от имени |
| Видео | `mp4`, `mov`, `avi`, `mxf`, `mkv`, `mpg`, `mpeg`, `wmv`, `mts`, `m2ts`, `webm` |
| Аудио | `mp3`, `wav`, `aif`, `aiff`, `flac`, `ogg`, `m4a`, `wma`, `aac` |
| Архивы | `rar`, `zip`, `7z`, `ace`, `arj`, `tar`, `gz`, `bz2`, `xz` |
| Изображения | `jpg`, `jpeg`, `png`, `tif`, `tiff`, `bmp`, `gif`, `tga`, `webp`, `exr`, `dpx` |
| Проекты / исходники | `aep`, `aepx`, `prproj`, `drp`, `veg`, `max`, `blend`, `c4d`, `psd`, `psb`, `ai`, `cdr`, `indd`, `fla` |
| Документы | `pdf`, `doc`, `docx`, `xls`, `xlsx`, `ppt`, `pptx`, `txt`, `rtf`, `odt` |
| Прочее | Неизвестное расширение, пустое расширение и иные файлы |

Если расширение есть одновременно в нескольких тематических наборах, должна применяться **одна** однозначная классификация (в частности, `psd`, `psb`, `ai` относить к «Проектам / исходникам»). Многотомные `*.part1.rar` и `*.part2.rar` классифицировать по последнему расширению `rar`. Файл с отображаемым именем `.DS_Store` не терять.

**Не изменяй способ хранения исходных имён и расширений в базе**. Группа — вычисляемое представление.

## 4. Производительность и взаимодействие

- Оставь **одну строку поиска**, кнопку **«Найти»**, запуск клавишей **Enter** и текущую семантику поиска: подстрока имени, `casefold`, все диски, все совпадения.
- Не вводи вкладки, флажки, фильтры, сортировку по типам с отдельными настройками или иные новые управляющие элементы.
- Сохрани фоновое выполнение поиска и отзывчивость UI. Не создавай отдельный тяжёлый виджет для каждой найденной строки: в отчёте этапа 2 проверено до ~149 тысяч совпадений.
- Желательная реализация: **QTreeView + модель на базе QAbstractItemModel**, с корневыми узлами-группами, а под ними строками результатов. Адаптируй существующую модель и порционную загрузку; не переводить десятки тысяч элементов в `QTreeWidget`/`QStandardItem` по одному без теста производительности.
- Новая поисковая выдача должна корректно обновляться при повторном поиске, при пустом запросе и при закрытии окна. Отменённые/устаревшие фоновые результаты не должны попадать в новую выдачу.
- Сохрани изменение ширины колонок и их читаемость. Пользователь должен иметь возможность увидеть **полное имя и путь** расширением окна или ширины колонок, без принудительной обрезки хранимых данных.

## 5. Что не менять

- **Не изменять `catalog.db`, схему SQLite и импортёр XML**, если для представления иконок/групп это не требуется. Никакой миграции БД.
- Не менять алгоритм поиска и его регистронезависимое сопоставление.
- Не менять удаление дисков, список носителей, существующие команды CLI и логику ленивого открытия папок.
- Кнопку **«ДОБАВИТЬ ДИСК»** оставить неактивной: сканирование физических DVD — **этап 3**.
- Не добавлять интернет-функции, облака, миниатюры, теги, категории для ручного редактирования или новые панели.
- **Рабочую базу не удалять и не модифицировать.** Проверки, способные менять данные, выполнять только на отдельных копиях.

## 6. Приёмка и проверки

После реализации выполни автоматизированные тесты первого и второго этапов и добавь тесты для доработки:

1. Запрос `Slavneft`: число найденных элементов **не меняется** относительно этапа 2 (16 файлов); среди них есть `Slavneft 2026.part1.rar` на диске **1514** и `Slavneft 2026.part2.rar` на диске **1515**, оба в группе «Архивы».
2. Проверить отдельно поиск, возвращающий папки, видео, аудио, изображения, проекты и неизвестные файлы, чтобы все восемь групп работали ожидаемо.
3. Одинаковые имена на разных дисках сохраняются отдельными результатами; каждый результат помещён **в одну** группу.
4. `.AVI`/`.avi`, `RAR`/`rar`, `*.part1.rar`, файлы без расширения и `.DS_Store` отображаются и классифицируются без ошибок.
5. Группы с нулём элементов скрыты; непустые раскрыты при первой выдаче; можно сворачивать/раскрывать группу; счётчик не включает заголовки групп.
6. В правой панели главного окна присутствуют иконки у папок и файлов. Диск **1514** по-прежнему содержит папку «Славнефть 65 лет» и архив внутри неё.
7. Большие выборки `1920x1080`, `.rar` и `.` не блокируют интерфейс. Проверить фактическое время получения и построения UI, потребление памяти и прокрутку; отметить отличия от показателей в `STAGE_02.md`.
8. Проверка целостности исходной `catalog.db` после работы и отсутствие изменений схемы/данных.

Сделай реальные снимки **главного окна** и **окна поиска** после изменений (желательно запрос, демонстрирующий несколько категорий) и сохрани в `stage_02a/`.
